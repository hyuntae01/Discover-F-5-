문서 개요

이 문서는 OfficeTone 웹앱을 구현하기 위한 화면 단위 설계 기준이다. 각 화면의 구성 요소, 상태, 전환 조건, 예외 처리를 정의하며 기획서와 디자인 가이드가 충돌할 경우 기획서를 우선한다.

핵심 기능

ID기능정의관련 화면
F-01상황에 맞는 문장 변환 원문(최대 300자)과 상대방·톤앤매너·전달 채널 선택값을 받아, 핵심 내용과 기한을 유지한 업무용 표현을 제안한다. SC-02
F-02전후 비교와 복사 원문과 변환문을 나란히 비교하고, 무엇이 왜 바뀌었는지 짧게 확인한 뒤 복사하거나 옵션을 고쳐 다시 변환한다. SC-03
F-03상황별 예문 자주 쓰는 5개 상황 카드를 고르면 예문과 옵션 3종이 입력 화면에 자동으로 채워진다. SC-04 SC-02

설계 전제

  • 로그인·회원가입·저장 기능 없음. 모든 상태는 세션 내 메모리로만 유지한다.
  • 화면은 4개로 고정하며 상세 화면·예문 전용 화면을 추가하지 않는다.
  • 문법 교정이 아니라 업무 표현의 재작성이 목적이다. 단어 단위 교정 UI는 사용하지 않는다.
  • 제품 화면은 라이트 톤 고정(흰색·밝은 회색 배경 + 파란 포인트)이며, 본 설계서의 목업은 가독성을 위해 문서 테마를 따른다.

상태

  • 빈 상태 — SC-01에서 진입. 입력창 비어 있고 옵션은 기본값, CTA 비활성.
  • 자동 입력 — SC-04 카드 선택으로 진입. 예문과 옵션 3종이 채워진 상태로 열리며 CTA는 바로 활성. 안내 배너·모달은 띄우지 않는다.
  • 수정 복귀 — SC-03의 문장 수정하기로 진입. 직전 원문과 옵션을 그대로 유지한다.
  • 변환 중 — CTA 라벨을 바꾸는 중…으로 바꾸고 중복 제출을 막는다.
옵션 선택 규칙 — 세 그룹 모두 항상 1개가 선택된 상태다. 해제 상태를 허용하지 않으므로 “선택 안 함” 칩을 만들지 않는다. 선택 여부가 색 차이만으로 미묘하게 보이지 않도록 테두리와 굵기를 함께 바꾼다.

상태 · 예외

  • 복사 완료 — C-TOAST 버튼 라벨이 복사했어요로 1.5초간 바뀐다.
  • 결과 없음 — 샘플 데이터에 없는 문장일 때: 안내 “샘플 데이터에 없는 문장이라 변환 결과를 보여드릴 수 없어요. 기본 예문을 그대로 쓰거나, 상황별 표현에서 예문을 골라 주세요.” 와 함께 SC-04로 가는 보조 버튼을 노출한다.
  • 클립보드 차단 — 복사 실패 시 변환문 영역을 전체 선택 상태로 바꾸고 “직접 복사해 주세요”를 보조 문구로 표시한다.

전환 규칙

  • 카드 레이아웃: 2열(모바일 1열). 5번째 카드는 2열을 가로로 채운다.

04

데이터 · 상태 모델

전역 상태는 하나의 객체로 충분하다. 화면 전환은 screen 값만 바꾸고 입력값은 유지한다.

앱 상태

// 세션 메모리에만 존재. 저장·동기화 없음
{
  screen:  'home' | 'input' | 'result' | 'situations',
  text:    string,   // 원문, 최대 300자
  target:  '상사' | '동료' | '후배' | '외부 고객',
  tone:    '부드럽게' | '기본' | '격식 있게',
  channel: '메신저' | '이메일',
  copied:  boolean    // 복사 피드백 1.5초 플래그
}

변환 결과

{
  result: {
    pre: string,   // 강조 앞 문장
    em:  string,   // 핵심 표현 1곳 — SC-03에서 굵기·색 강조
    post:string    // 강조 뒤 문장
  },
  changes: [
    ['재촉하는 질문', '진행 상황 확인 표현으로 변경'],  // A → B 형식
    '지시형 문장을 부드러운 요청으로 변경',              // 단문 형식
    '핵심 내용(자료·오늘까지)은 그대로 유지'             // 마지막 줄은 항상 유지 항목
  ]
}

화면 전환 시 상태 처리

전환트리거상태 처리
SC-01 → SC-02문장 바꾸러 가기text를 비우고 옵션은 기본값으로 초기화한다.
SC-01 → SC-04상황별 표현 보기상태 변경 없음.
SC-04 → SC-02상황 카드 선택선택 카드의 P-0n 프리셋으로 text·target·tone·channel을 한 번에 덮어쓴다.
SC-02 → SC-03회사 말투로 바꾸기입력값 유지. 매칭되는 프리셋이 없으면 결과 없음 상태로 진입한다.
SC-03 → SC-02문장 수정하기입력값·옵션을 그대로 유지한 채 화면만 되돌린다. 초기화 금지

제약 사항

구현·개선 과정에서 흔들리기 쉬운 지점을 못 박는다. 왼쪽은 유지, 오른쪽은 조정 가능.

반드시 유지조정 가능
4개 화면 구조와 사용자 흐름 여백, 요소 간격, 카드·버튼 크기
상대방 / 톤앤매너 / 전달 채널 3그룹 선택 구조 선택 상태의 표시 방식(테두리·배경·굵기 조합)
기존 문장 → 변환 결과 비교 흐름과 “이렇게 바뀌었어요” 영역 전후 문장의 시각적 구분 방식, 변화 설명의 가독성
상황 카드 선택 → SC-02 이동 → 예문·옵션 자동 입력 카드 그리드 열 수, 아이콘 표현, hover 인터랙션
파란색 중심 디자인 방향과 확정 문구 글자 크기·굵기, 정보 위계, 모바일 대응

하지 않는 것

  • 화면·기능 임의 추가, 확정 기능 삭제
  • 상황 카드별 상세 화면이나 예문 전용 페이지 추가
  • DeepL식 밑줄 교정 표시를 그대로 적용하는 것 — 변화는 설명 영역으로 전달한다
  • 레퍼런스 서비스의 전체 레이아웃·브랜드 컬러 복제
  • 과도한 그라데이션·그림자·장식, 화려한 애니메이션
  • 한 화면에 설명문을 여러 블록으로 나눠 붙이는 것
